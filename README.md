## Round 3 반영

- 2차 버전은 `poc/web-old/round2/`에 보관했습니다. 기존 구조와 디자인을 유지하고 2차 피드백의 3건을 수정했습니다.
- 언어 선택은 선원 앱바 오른쪽의 지구본 + `ID / EN / VI / FIL` 칩 한 개로 통일했습니다. 본문과 가입 안내의 중복 선택상자를 제거했습니다. 키보드로 조작할 수 있는 네이티브 선택상자를 칩에 연결하고, 변경 후 포커스를 유지합니다.
- 발행 직후 선원 첫 카드에 `Laporan siap · Report ready`, `HB-2026-1105`, 실제 승인 상태에서 계산한 시정 승인 2건과 `15150 · ISM` 증빙 준비 중 1건을 표시합니다. 이전 미완료 과제 목록 대신 보고서 열기 버튼이 표시됩니다.
- `.phone-body`의 아래쪽에 하단 탭 높이 + 16px 여백을 공통 적용했습니다. 모바일과 데스크톱 모두 마지막 요소 아래에 여백이 남습니다.
- 검증: JavaScript 구문 검사, 상태 검사 **50 PASS**, DOM 검사 **39 PASS**, HTML 14개 문서/조각의 닫힘 태그·중복 ID 검사 통과. 파일 15개, 약 2.63MB(3MB 미만).
- `test-web.mjs`에는 언어 칩 단일성·언어 전환·보고서 완료 상태·하단 여백 회귀 검사를 추가했습니다. 실행은 Chromium 시작 단계에서 macOS sandbox의 `bootstrap_check_in ... Permission denied (1100)`으로 실패했습니다. **브라우저 E2E, 390/1280 실측 레이아웃과 새 스크린샷은 미검증**이며 외부 실행이 필요합니다. 결과는 `_codex/validation/*-round3.*`에 있습니다.
- `shot.mjs`는 외부 실행용이며, 기존 촬영에 `5-ready`(선원 역할의 보고서 완료 화면)를 추가했습니다. 두 폭 합계 20장을 저장합니다. `submission/` zip은 만들지 않았습니다.

## Round 2 반영

- 1차 버전은 `poc/web-old/round1/`에 보존했습니다. 남색 업무 화면·두 역할 배치를 유지하며 피드백 전체를 반영했습니다.
- 토스트는 하단 작업영역 높이 + 16px 위에 나타나고 2.5초 뒤 닫힙니다. 작업바는 일반 문서 흐름에 놓고 전달 완료는 초록 확인 줄로 표시합니다.
- 우선순위 행은 64px 기준이며 영어 이름·근거 칩과 출처를 제공합니다. 상단 `예외 보기: 기항지 바꾸기`에서 일본 지바를 선택하면 순위 변화 수와 ▲▼를 표시합니다.
- 선원 화면은 선택 언어와 영어로 표시합니다. 한국어 항목명은 접힌 `한국어 보기`에만 둡니다. 연결/오프라인 전환은 상단 시연 띠에서 합니다.
- 장면2 최초 진입은 로컬 답변 3건·사진 2장 대기 상태입니다. `빠르게 채우기`로 6건·3장으로 늘리고, `연결`하면 사무실에 답변과 미비 2건이 반영됩니다. 폰 내부는 스크롤하며 질문·응답 버튼을 먼저 보여 줍니다. 언어 설정은 Round 3에서 앱바로 옮겼습니다.
- 검토 목록은 사진 확인·미비를 먼저 표시합니다. 재촬영은 사진과 사유 선택칩을 함께 보여 줍니다.
- 1280px 보고서 분석은 원문과 결과 2열이며, 선원 폰에는 증빙 요청 카드가 가장 먼저 도착합니다.
- 보고서에 D-4 → D-3 → D-2 답변 수신 경과와 선 요소 서명란을 넣었습니다. `예외 보기: 미응답`은 원기록을 바꾸지 않는 미응답 2건 상황이며 발행 버튼과 이유를 첫 화면에 표시합니다. `예외 닫기`로 원래 화면에 돌아갑니다.

## 한 항차의 흐름

| 장면 | 핵심 동작 | 성공 확인 |
|---|---|---|
| 1 · 항차 등록 | 항차 등록 → 기항지·입항일 변경 → 배로 보내기 | 표준 위험 3점, 점검 창, CIC, 근거 있는 상위 12항목 |
| 2 · 선내 점검 | 예/아니오·사진·메모, 위쪽 `빠르게 채우기`, 연결 전환 | 오프라인 답 6건·사진 3장 → 사무실 미비 2건 |
| 3 · 검토 | 사진 재촬영 요청, 시정 지시 | 기관장 폰에 인도네시아어 알림·기한 |
| 4 · 지난 보고서 | 6월 부산 Form B 불러오기 → 증빙 요청 | 결함 3건, ISM 증빙 누락 1건, 자료 3개 요청 |
| 5 · 보고서 | 선원 시정 사진 → DPA 승인 2건 → 나머지 답변 수신 → 발행·공유 | 31/31 점검, 29 이상 없음, 2 시정 완료, 선장 보고서 |

처음 열 때는 선대 화면입니다. 선원 탭의 시작 버튼에서 초대 계정 연결·동의를 진행할 수 있습니다. 카메라·위치·알림 권한은 요청하지 않습니다. 선장 화면에서 담당 변경이 가능합니다.

`#scene-1`…`#scene-5`, `#done`을 지원합니다. 장면을 건너뛰거나 새 브라우저에서 중간 장면을 열면 해당 장면의 선행 가상 기록을 불러오며 토스트로 알립니다. 기존 답변을 완료했다고 임의로 덮어쓰지 않습니다. 초기화는 마지막 화면에서 CSV를 내보낸 뒤 선택할 수 있습니다.

## 구현 범위와 모의 범위

- 화면·입력·검색·필터·사진 첨부·오프라인 저장·전송 대기열·시정 요청·승인·발행 제한·CSV 다운로드·인쇄·역할 간 상태 반영은 실제 브라우저 코드로 동작합니다.
- `localStorage` 키는 `psc-precheck-v2`입니다. 저장 공간 오류를 안내합니다. 같은 출처의 다른 탭은 `storage` 이벤트로 갱신합니다. `file://`의 파일별 저장 정책은 브라우저마다 다르므로 파일 간 공유가 제한되면 같은 페이지의 역할 탭을 사용합니다. HTTPS의 같은 출처에서는 `index.html`·`full.html`이 공유합니다.
- 실제 선박·사람·선사 서버·메신저·AI API를 연결하지 않았습니다. 선장 공유와 문의 저장은 현재 브라우저 안에서만 일어납니다.
- 업로드 영역은 파일 형식·10MB 제한을 확인하며, 임의 PDF를 읽었다고 주장하지 않습니다. 제공된 부산 Form B의 사전 구조화 결과 3건만 표시합니다.
- 사진은 생성형 이미지로 만든 가상 설비 2장입니다. 실제 카메라 촬영·실시간 이미지 압축은 수행하지 않습니다. `4.1MB → 280KB`는 요구 명세의 전송량 모델이며 화면에서도 표시합니다. 배포 파일은 미리 최적화한 로컬 JPEG입니다.
- 오프라인 저장은 이미 열린 화면과 로컬 파일에서 동작합니다. HTTPS에서 새로 방문할 페이지를 오프라인 설치하는 서비스 워커/PWA는 포함하지 않았습니다.
- 한국어·영어·인도네시아어 문구를 수록했습니다. 베트남어·필리핀어는 번역 준비 중임을 알리고 영어로 표시합니다. 전문 번역 검수는 미완료입니다.
- 기준 선박 조건은 벌크선·선령 14년·대한민국 기국 High·가중점 3점입니다. 가상의 선급/회사/이력 조건을 화면의 위험도 근거에서 공개합니다. 선급 이름은 비워 둡니다.
- 전체 목록은 제공 데이터의 일반 20개 + CIC 세부 11개 = 31개입니다. CIC는 번호 문항 10개를 1a/1b로 나눠 11행입니다. 기록 화면은 가상 과거 기록 100건과 새 활동을 검색·페이지 처리합니다.
- 가중치는 제품의 준비 우선순위 규칙이며 공식 NIR 산식·항만별 개별 결함 예측이 아닙니다. 중국 같은 당국에서는 순위가 유지되고 일본으로 바뀌면 억류 다발 항목의 상대 가중치가 바뀝니다. 산식은 화면에서 확인합니다.
- 31개 점검과 현재 시정이 완료돼도 지난 지적 15150의 증빙은 준비 중으로 남겨 보고서에 포함합니다. 미응답·담당 미지정·승인 대기·사진 재촬영·오프라인 대기는 발행을 막습니다.
- 보관 3년은 명세의 운영 설계 안내입니다. 현재 로컬 저장소에 3년 자동 삭제 스케줄이나 서버 권한 제어를 구현한 것은 아닙니다.

## 검증·촬영

```sh
node --check poc/web/app.js
node poc/web/state-test.mjs
PW_ROOT=/path/to/playwright-project node poc/web/test-web.mjs
PW_ROOT=/path/to/playwright-project node poc/web/shot.mjs
```

Playwright 로드는 `createRequire(process.env.PW_ROOT + '/')('playwright')`입니다. `BASE_URL=https://.../index.html`을 추가하면 배포본도 시험할 수 있습니다. `journey.mjs`는 두 스크립트가 공유하는 실제 조작 시나리오입니다.

- `test-web.mjs`: 390×844·1280×800 전체 흐름, 입력·동의·재계산·오프라인·반려·업로드 오류·차단·공유·CSV·기록 검색·해시·뒤로가기·pageshow·overflow·외부 요청·콘솔 오류를 검사합니다. 실패 시 종료 코드 1.
- `shot.mjs`: 실제 버튼을 조작하고 토스트 종료와 전환 완료 후 촬영합니다. 각 폭에서 `1`, `1-change`, `2a`(오프라인 대기), `2b`(전송 완료), `3-reject`(반려 사유), `3`, `4`, `5-blocked`(미응답), `5-ready`(선원 보고서 완료), `5`를 촬영해 `_codex/shots/demo-<장면>-<390|1280>.png` 총 20장을 만듭니다. `SHOT_FULL=1`이면 전체 높이 파일도 추가합니다. 기존 라운드 스크린샷과 혼동하지 않도록 외부 실행 시 새 결과를 확인하세요.
- Round 2: JavaScript 구문 검사, 상태 로직 49개, JSDOM DOM 동작 21개(총 70개) 통과. HTML 14개 문서/조각의 닫힘 태그·중복 ID를 검사했습니다. 최종 파일은 15개, 약 2.61MB입니다. 검증 결과는 `_codex/validation/`에 있습니다.
- `test-web.mjs` 실행을 시도했지만 Chromium 시작 단계에서 macOS sandbox의 `bootstrap_check_in ... Permission denied (1100)`으로 차단됐습니다(브라우저 검사 0 PASS / 시작 실패 1건). 요청대로 `shot.mjs` 촬영은 외부 실행용으로 준비했습니다. **실제 화면 스크린샷, 390/1280 레이아웃, 인쇄 페이지 수, Playwright 브라우저 E2E는 이 환경에서 확인하지 못했습니다.** 외부 실행 결과와 혼동하지 않습니다.

초기 사이트는 `poc/web-old/`, Round 1은 그 아래 `round1/`, Round 2는 `round2/`에 보존했습니다. 기획서 PDF, 기존 제출 zip, 공개 배포본은 수정하지 않았습니다.
